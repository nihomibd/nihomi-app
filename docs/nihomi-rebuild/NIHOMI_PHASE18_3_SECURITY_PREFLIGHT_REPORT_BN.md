## ৩. Supabase RLS হার্ডেনিং স্ক্রিপ্ট স্ট্যাটিক রিভিউ (Static Review: 20261016_supabase_rls_security_hardening.sql)

২৭টি টেবিলের উপর রো-লেভেল সিকিউরিটি (RLS) প্রয়োগের প্রভাব বিশ্লেষণ:

### ৩.১ পাবলিক কনটেন্ট টেবিলসমূহ (৯টি টেবিল)
`Course`, `Module`, `Lesson`, `LessonItem`, `Vocabulary`, `Grammar`, `Kanji`, `Quiz`, `QuizQuestion`
- **প্রস্তাবিত নীতি:** `FOR SELECT TO anon, authenticated USING (true)`
- **ব্রাউজার রাইট পারমিশন:** কোনো পাবলিক ইউজার বা শিক্ষার্থী ব্রাউজার থেকে সরাসরি এই টেবিলগুলোতে `INSERT`, `UPDATE`, বা `DELETE` করতে পারবে না।
- **প্রভাব:** লার্নিং ক্যানভাস ও লেসন প্লেয়ার স্বাভাবিকভাবে কনটেন্ট পড়তে পারবে। কোনো ব্রেকিং চেঞ্জ নেই।

### ৩.২ শিক্ষার্থী-মালিকানাধীন ব্যক্তিগত টেবিলসমূহ (৯টি টেবিল)
`User`, `Profile`, `LessonProgress`, `LearningProgress`, `MistakeRecord`, `QuizAttempt`, `Subscription`, `Invoice`, `UsageRecord`
- **প্রস্তাবিত নীতি:** `USING (auth.uid()::text = "userId") WITH CHECK (auth.uid()::text = "userId")`
- **নিরাপত্তা ফলাফল:** একজন শিক্ষার্থী অন্য কোনো শিক্ষার্থীর প্রগ্রেস, স্কোর, ব্যক্তিগত প্রোফাইল বা চালান দেখতে বা পরিবর্তন করতে পারবে না।
- **প্রভাব:** ক্লায়েন্ট কোড যখন Supabase Auth দিয়ে লগইন থাকবে তখন সে নির্বিঘ্নে নিজের ডাটা এক্সেস করবে।

### ৩.৩ অভ্যন্তরীণ সার্ভার-অনলি ও আর্থিক টেবিলসমূহ (৯টি টেবিল)
`Payment`, `PaymentAttempt`, `WebhookEvent`, `SubscriptionEvent`, `AdminAuditLog`, `Coupon`, `coin_wallets`, `coin_transactions`, `nihomi_reward_events`
- **প্রস্তাবিত নীতি:** `REVOKE ALL FROM anon, PUBLIC` এবং শুধুমাত্র ব্যাকএন্ড `service_role` দিয়ে ম্যানেজ করা।
- **পেমেন্ট ভিউ নীতি:** শিক্ষার্থীরা শুধুমাত্র নিজের পেমেন্ট স্ট্যাটাস রিড করতে পারবে (`SELECT USING (auth.uid()::text = "userId")`), কিন্তু পেমেন্ট তৈরি বা সফল হিসেবে মার্ক করতে পারবে না।
- **নিরাপত্তা ফলাফল:** ক্লায়েন্ট ব্রাউজার থেকে জাল পেমেন্ট বা সাবস্ক্রিপশন ইনজেক্ট করার ঝুঁকি শূন্য।

### ৩.৪ রোলব্যাক স্ক্রিপ্টের সীমাবদ্ধতা (Rollback Limits)
- প্রস্তুতকৃত [20261016_supabase_rls_security_hardening_rollback.sql](file:///c:/Users/bdtri/Desktop/www.Nihomi.com/nihomi-app-1/prisma/migrations/20261016_supabase_rls_security_hardening_rollback.sql) স্ক্রিপ্টটি সমস্ত পলিসি ড্রপ করে পূর্বের অবস্থায় ফিরিয়ে দেয়। তবে নিরাপত্তার স্বার্থে এটি টেবিলের RLS বন্ধ করে না। সম্পূর্ণ পূর্বাবস্থায় ফিরতে DBA-কে `ALTER TABLE ... DISABLE ROW LEVEL SECURITY;` চালাতে হবে।
- **বাধ্যতামূলক নীতি:** ফাউন্ডারের পৃথক অনুমোদন ও ক্লাউড ব্যাকআপ নেওয়ার আগে লাইভ ডাটাবেসে এটি স্বয়ংক্রিয়ভাবে এক্সিকিউট করা সম্পূর্ণ নিষিদ্ধ।
